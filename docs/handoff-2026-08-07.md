# Handoff — 2026-08-07

## 1. Kiosk de Producción: token de dispositivo, además de IP/CIDR

El acceso a `/job-kiosk` dependía solo de `RestrictToLabNetwork` matcheando
IP/CIDR (`KioskNetwork.ip_address`). El usuario reportó que a veces se corta
— la tablet cambia de IP (reconexión, roaming del prefijo IPv6) y queda
afuera hasta que alguien vuelve a cargar la IP nueva en Admin → Acceso
Kiosk. Se pidió algo "infalible" que no dependa de la red.

El middleware ya soportaba un token (`KioskNetwork.token`, revisado antes
que la IP), pero no había UI para gestionarlo — solo existía el fallback de
`.env` pensado para desarrollo. Se agregó:

- **Backend**: `KioskAccessController::storeDeviceToken()` /
  `toggleDeviceToken()` / `destroyDeviceToken()` — crean/gestionan filas
  `KioskNetwork` con `token` (random de 48 chars) en vez de `ip_address`.
  Rutas nuevas bajo `admin.kiosk-access.device-tokens.*`
  ([routes/modules/admin.php](../artdent-crm/routes/modules/admin.php)).
- **UI**: nueva sección "Tokens de dispositivo — Kiosk de Producción" en
  `Admin/KioskAccess.jsx`, mismo patrón visual que la lista de IPs. Al crear
  un token muestra el link completo (`.../job-kiosk?token=...`) una sola
  vez, igual que los tokens de API existentes.
- **Frontend del kiosk** (`JobKiosk/Index.jsx`): hook `useKioskDeviceToken()`
  lee `?token=` de la URL al montar, lo persiste en `localStorage`
  (`job_kiosk_device_token`) y lo setea como header `X-Kiosk-Token` default
  de `axios` — así todas las llamadas del módulo (`available-jobs`,
  `take-phase`, `complete-phase`, etc., no solo la carga inicial de la
  página) lo mandan automáticamente, sin tocar cada call site.
- Las IPs existentes se dejaron como están — el token es un método
  adicional, no un reemplazo. Explícitamente **no** se tocó el kiosk de
  fichaje (Raspberry) — quedó inutilizable, reemplazado por los lectores
  Hikvision ISUP/ISAPI (ver `project_hikvision_isup_integration` en
  memoria).

**Token real generado en producción** para la tablet del taller (`tenant_id
= artdent`, `KioskNetwork#6`, label "Tablet taller (producción)"). Cargado
en la tablet **sin reinstalar la app**: mismo truco de ADB + Chrome
DevTools Protocol usado antes con la config de la impresora — puerto
forwardeado al socket `webview_devtools_remote_<pid>` de la WebView activa,
`Runtime.evaluate` para `localStorage.setItem('job_kiosk_device_token',
'...')`, `Page.reload` para que el hook lo levante. No hizo falta editar
`capacitor.config.json` ni recompilar el APK — sigue apuntando a
`https://pos.artdent.com.ar/job-kiosk` sin `?token=` en la URL fija, el
token vive en `localStorage` del dispositivo.

Deploy: 4 archivos (controller, rutas, 2 páginas React) subidos por SSH +
build de Vite (`VITE_REVERB_FORCE_LOCAL=false npm run build`) + swap de
`public/build`. Verificado `php -l` en cada archivo PHP subido y que
`/job-kiosk?token=<token real>` responde 200. No se pudo verificar en
negativo (token inválido → 403) desde esta red porque la IP de esta PC ya
está en la whitelist de IPs por separado, así que cualquier request desde
acá pasa igual — el código del middleware se revisó directamente en cambio
(`KioskNetwork::where('token', $token)->where('is_active', true)` antes de
llegar a la resolución por IP).
